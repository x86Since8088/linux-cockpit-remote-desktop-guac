How a connection reaches a desktop

Opening this tab leaves a live connection on Connect running. The browser opens no network connection to guacd or to a desktop. Cockpit's HTTPS session carries the frames to a local relay, and a firewall rule lets only the relay's user (and root) open guacd. Before some connections this page does read or set gnome-remote-desktop settings through Cockpit: the port-3389 sharing mode and, in automatic sign-in, the door key (port 3389's from your own keyring; port 3390's, for the login screen, with administrative access).

  • Code in this plugin
  • Not changed by this plugin: distro packages, guacd (a third-party build pinned by digest), and other people's servers
  • gnome-remote-desktop as rebuilt on edt1 with the handover patch (other hosts run the stock package)
  • A group this plugin starts

Login screen uses the whole RDP bridge. This page, the relay, the firewall rule, and the bridge script are this plugin. Cockpit, Xvfb, x11vnc, and xfreerdp3 are unmodified distro packages; guacd is a pinned third-party build (Janua, guacd built against FreeRDP 3). On edt1, gnome-remote-desktop is a locally rebuilt daemon that carries the handover patch, and the login screen is the path that needs it. After you sign in, gnome-remote-desktop moves the connection onto a desktop session of your own that has no seat, so it is not the physical screen. A later connection to port 3390 is handed back to that same session.

Console uses the same bridge and lands on port 3389 as a mirror of the physical screen; this page sets that port's screen-share mode to mirror before it connects. It does not go through the greeter, except that this page opens the Login screen instead when nobody is signed in at the physical seat. Port 3389 is served by the signed-in user's own gnome-remote-desktop; on edt1 it is the same rebuilt file as the login-screen door, but the handover patch is not used on this path. The programs inside the bridge are unmodified distro packages.

A virtual monitor uses the same bridge and asks port 3389 for an extra monitor inside your own session; this page sets that port's screen-share mode to extend before it connects, so switching between Console and Virtual monitor changes what the one per-user daemon delivers. Port 3389 is served by the signed-in user's own gnome-remote-desktop; on edt1 it is the same rebuilt file as the login-screen door, but the handover patch is not used on this path. The programs inside the bridge are unmodified distro packages.

Isolated uses the same bridge to your own headless desktop, a second GNOME with its own gnome-remote-desktop, on port 33000 + (uid − 1000), for uids 1000 to 1999. It is refused while you are signed in at the machine's own screen. The relay starts it on demand through a starter that is this plugin and is not drawn here. Xvfb, x11vnc, and xfreerdp3 are unmodified distro packages; guacd is the pinned third-party build. On edt1 the headless gnome-remote-desktop is the same rebuilt file as on the login screen, but the handover patch is not used on this path.

Wayland stops at guacd. guacd speaks VNC, so the bridge stays dark. The relay starts the desktop through the Wayland starter, which is this plugin. sway and wayvnc are unmodified, on port 34000 + (uid − 1000). wayvnc listens on loopback with no password, and no firewall rule covers its port, so any local user on this host can connect to it directly; the relay only decides who is told the port.

Remote RDP still uses the bridge. Unmodified xfreerdp3 dials the address you typed. The relay, which is this plugin, checks that address and port against the allow-list before anything is started. Their RDP server is whatever runs there; it is not our patched gnome-remote-desktop.

Remote VNC stops at guacd, the same way Wayland does. guacd dials their VNC server. The bridge is not started. The relay checks the address and port against the allow-list; an entry with no port means 3389, so a VNC server on 5900 needs :5900 or :*.

Each RDP connection gets its own bridge. xfreerdp3 speaks to gnome-remote-desktop and draws into a private Xvfb, and x11vnc publishes that screen on a loopback port with a per-connection password. guacd dials x11vnc over VNC, and xfreerdp3 dials gnome-remote-desktop. The bridge exists because the guacd RDP client this design started with (the official image, FreeRDP 2) could not complete the RDSTLS redirect on port 3390 (KNOWN_ISSUES I26) or connect to gnome-remote-desktop's port 3389 (requires.txt), and an earlier FreeRDP 3 guacd regressed port-3389 rendering (I29). The pinned guacd image now links FreeRDP 3, but this plugin does not use its RDP client. Closing the connection removes the bridge. Your desktop session keeps running: a seated desktop indefinitely, an isolated or Wayland desktop for about 15 minutes after the last connection, and a login screen that nobody signed in to is closed after about a minute.

Login screen 127.0.0.1:3390, NLA, door key held on the server (this page reads it with administrative access) The GDM greeter. After you sign in, your desktop. That desktop is a headless session with no seat, so it is not the physical monitor.
Console 127.0.0.1:3389, NLA, mirror of the physical screen The screen on the machine. Requires administrative access, and the shadow group when someone else is signed in at the seat. With nobody signed in on the physical seat, Connect opens the login screen instead. A headless desktop from the login screen has no seat, so it does not count as someone being at the console.
Virtual monitor 127.0.0.1:3389, NLA, extend An extra monitor inside your own logged-in session.
Isolated session 127.0.0.1, port 33000 + (uid − 1000) Your own headless GNOME desktop, started on demand. The relay supplies the credential from your Cockpit identity. The first start takes about 20 seconds. A reconnect inside the idle window returns to the same desktop. Refused while you are signed in at the machine's own screen, and only for uids 1000 to 1999.
Wayland desktop 127.0.0.1, port 34000 + (uid − 1000) Your own sway desktop over VNC. No door key and no VNC password: it listens on a loopback port that any local user on this host can reach, and guacd connects to it directly.
Remote host (RDP) The IPv4 address you type That computer's RDP server. The address and port have to be on the administrator's allow-list. The server's certificate is pinned on first use and forgotten at reboot.
Remote host (VNC) The IPv4 address you type That VNC server, dialed by guacd directly, on the same allow-list (a bare entry means port 3389, so VNC on 5900 needs :5900 or :*). A password is sent only if that server asks for one.

Login screen, and the desktop it opens

The door key lets the connection in. The password you type at the greeter is what signs you in. gnome-remote-desktop then moves that connection from the greeter onto your desktop: first onto a headless greeter, then onto the handover daemon inside your session.

The session keeps running if the browser connection dies. The window can keep showing the last frame after the bridge is gone. Mouse and keyboard work only while a connection is attached. When the sign-in connection drops on its own, this page opens one new connection to port 3390, and gnome-remote-desktop hands it to the desktop you already signed into. The session stays logged in. Disconnect, an explained error, and a second drop before the new connection has been up for 15 seconds leave the page disconnected. Changing sound or resolution reconnects on its own and does not use this follow.

What a disconnect removes

  • Removed with the connection: the FreeRDP bridge (xfreerdp3, Xvfb, x11vnc) and the guacd client.
  • Left running, for now: your desktop session and its gnome-shell. A seated desktop stays; an isolated or Wayland desktop is reaped about 15 minutes after the last connection, and a login screen nobody signed in to about a minute after. After a login-screen sign-in, the handover daemon stays too.
  • Active Sessions asks the relay for its list over the control socket. The relay keeps that list in /run/edy-rdp/state/sessions.json on a tmpfs, so it is empty after a reboot, together with every bridge.

Who is allowed through

  • The cockpit-guac-rdp group is required to open the relay socket.
  • Console always requires Cockpit administrative access, and the relay checks a proof from the server, not the state of a control on this page. The login screen is not admin-gated by the relay: any member of the cockpit-guac-rdp group who holds the door key can reach it, and this page asks for administrative access only because reading that key needs it. Remote hosts (RDP and VNC) require administrative access only when the administrator sets EDY_RDP_REMOTE_ADMIN_ONLY=1.
  • Mirroring a physical screen where someone else is signed in also requires the shadow group.
  • An isolated session and a Wayland desktop are started for the uid the kernel reported (SO_PEERCRED). The page cannot aim them at another user.
  • A remote host must match an entry in EDY_RDP_REMOTE_ALLOW: an IPv4 address or range, with an optional port (no port means 3389, :* means any port). An empty list denies every remote target.
  • guacd listens only on the host's loopback address (127.0.0.1:4822); it is not published to the network, and the firewall rule lets only the relay's user and root connect to it.
  • That firewall rule covers only guacd's port and the isolated-session ports 33000-33999. This plugin installs no firewall rule for gnome-remote-desktop's ports 3389 and 3390 (they listen on every interface on edt1; NLA protects them, KNOWN_ISSUES I7) or for the Wayland ports 34000-34999, which also have no password.

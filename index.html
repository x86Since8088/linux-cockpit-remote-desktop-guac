How a connection reaches a desktop

Opening this tab leaves a live connection on Connect running. The browser never talks to guacd or to gnome-remote-desktop. Cockpit's HTTPS session carries the frames to a local relay, and the relay is the only program allowed to open guacd.

browser
  Cockpit HTTPS (your Cockpit login)
    cockpit-bridge, running as you
      edy-rdp-relay on /run/edy-rdp/guacd.sock
        the kernel reports your uid (SO_PEERCRED)
        nftables admits only the relay user to 127.0.0.1:4822
          guacd
            RDP session: x11vnc → Xvfb ← xfreerdp3 → gnome-remote-desktop
            VNC session: guacd's own VNC client, no FreeRDP bridge

Each RDP connection gets its own bridge. xfreerdp3 speaks to gnome-remote-desktop and draws into a private Xvfb, and x11vnc publishes that screen on a loopback port with a per-connection password. guacd's built-in RDP client cannot complete this handshake, which is why the bridge exists. Closing the connection removes the bridge. The desktop behind it stays.

Session choices

SessionWhere it connectsWhat you get
Login screen 127.0.0.1:3390, NLA, server-held door key The GDM greeter. After you sign in, your desktop. That desktop is a headless session with no seat, so it is not the physical monitor.
Console 127.0.0.1:3389, NLA, mirror of the physical screen The screen on the machine. Requires administrative access, and the shadow group when someone else is signed in at the seat. With nobody signed in on the physical seat, Connect opens the login screen instead. A headless desktop from the login screen has no seat, so it does not count as someone being at the console.
Virtual monitor 127.0.0.1:3389, NLA, extend An extra monitor inside your own logged-in session.
Isolated session 127.0.0.1, port 33000 + (uid − 1000) Your own headless GNOME desktop, started on demand. The relay supplies the credential from your Cockpit identity. The first start takes about 20 seconds. A reconnect inside the idle window returns to the same desktop.
Wayland desktop 127.0.0.1, port 34000 + (uid − 1000) Your own sway desktop over VNC. No door key. Loopback only, and guacd connects to it directly.
Remote host (RDP) The IPv4 address you type That computer's RDP server. The address has to be on the administrator's allow-list. The certificate is stored on first use.
Remote host (VNC) The IPv4 address you type That VNC server, dialed by guacd directly, on the same allow-list. A password is sent only if that server asks for one.

Login screen, and the desktop it opens

The door key lets the connection in. The password you type at the greeter is what signs you in. gnome-remote-desktop then moves that connection from the greeter onto your desktop: first onto a headless greeter, then onto the handover daemon inside your session.

The session keeps running if the browser connection dies. The window can keep showing the last frame after the bridge is gone. Mouse and keyboard work only while a connection is attached. When the sign-in connection drops on its own, this page opens one new connection to port 3390, and gnome-remote-desktop hands it to the desktop you already signed into. The session stays logged in. Disconnect, an explained error, and a second drop before the new connection has been up for 15 seconds leave the page disconnected. Changing sound or resolution reconnects on its own and does not use this follow.

What a disconnect removes

  • Removed with the connection: the FreeRDP bridge (xfreerdp3, Xvfb, x11vnc) and the guacd client.
  • Left running: your desktop session and its gnome-shell. After a login-screen sign-in, the handover daemon stays too.
  • Active Sessions reads the relay's list in /run/edy-rdp/state/sessions.json. That file lives on a tmpfs and is empty after a reboot, together with every bridge.

Who is allowed through

  • The cockpit-guac-rdp group is required to open the relay socket.
  • Console, the login screen, and remote hosts require Cockpit administrative access. The relay checks a proof from the server, not the state of a control on this page.
  • Mirroring a physical screen where someone else is signed in also requires the shadow group.
  • An isolated session and a Wayland desktop are started for the uid the kernel reported. The page cannot aim them at another user.
  • A remote host must be an IPv4 address listed in EDY_RDP_REMOTE_ALLOW. An empty list denies every remote target. guacd itself is never published on a host port.
